# 4.0.0 migration notes (working file)

Collected while the 4.0.0 work lands on `windows-support`; the release (sub-project E) turns this into the CHANGELOG's
migration table and deletes the file.

## Source changes a host may need

| Change | Who is affected | What to do |
| --- | --- | --- |
| `MixLevel` and `MasterOutputStage` moved from `SheetMusicAudioApple` to `SheetMusicAudioCore` (shared with the Windows engine) | Code that imports `SheetMusicAudioApple` directly and names either type. The `SheetMusicAudio` umbrella re-exports both modules, so its users are unaffected | `import SheetMusicAudioCore` |
| `ScoreReplacementOutcome` moved from `SheetMusicAudioApple` to `SheetMusicAudioCore` (the Windows engine's `replaceScore(with:)` returns it too) | Same as the row above | `import SheetMusicAudioCore` |
| `WindowsPlaybackEngine` (Windows only) now mirrors the Apple `PlaybackEngine`'s operations: `init(soundFontPath:)`, `load(_:)`, `play()`, `position`, `totalPlayerSeconds`, `isAtEnd`, `isRunning` and `channelPrograms` are gone | Anything written against the W0 probe surface | `init(soundfontResolver:metronomeClickProvider:)`, `prepare(score:)`, `play(from:in:countIn:)`, `currentCursor`, `currentTimeSeconds`, `state`, `onEvent` |
| `SynthBackend` no longer supplies defaults for `play(afterCountInSeconds:)`, `setMetronomeVolume(_:)`, `setUnrolledTimeMap(_:)` and `makeOfflineInstance(sampleRate:)` (the `isReady`, `onReadyChanged` and `isAtEnd` defaults stay) | Custom `SynthBackend` conformers, including test doubles, that relied on any of the four. `SwiftySynthBackend` users are unaffected | Implement all four. The old behavior, if it is really what the backend means: `play(afterCountInSeconds:)` calls `play()`, the two setters do nothing, `makeOfflineInstance` returns `nil` (the export then falls back to AUMIDISynth). A time-based transport that ignores `setUnrolledTimeMap` seeks into the wrong measure-play on any score with repeats |
| `PlaybackEngine.previewNoteOn(pitch:onStaff:velocity:atTick:)` and the Windows engine's twin no longer default `atTick` to `0` | Every caller of `previewNoteOn` that omitted `atTick` | Pass the tick of the note's position (the caret / selection tick). The channel is resolved at that tick, so after a mid-score instrument change only the right tick auditions the new instrument; `0` always sounds the part's opening one |
| `MasterOutputStage.peakLimiter` is gone, with the `AUPeakLimiter` node behind it (Kotlin: `MasterOutputStage.PEAK_LIMITER`, which already behaved as `NONE`) | Hosts that select the peak limiter | `.softClip` to keep a boost from clipping hard (loudness keeps rising with the gain, unlike the limiter), or `.none` |
| Kotlin `AndroidPlaybackEngine.setMasterVolume(volume:)` (deprecated since the gain was uncapped) is gone | Android hosts still calling it | `setMasterGain(gain)` — same value, same behavior |
| `FontMetricsProvider` no longer supplies defaults for `textInkBounds(text:font:)` and `leading(font:)` (the `renderingTextFont(_:)` identity default stays) | Custom `FontMetricsProvider` conformers that relied on either. `AppleFontMetricsProvider`, `StubFontMetricsProvider` and the metrics-table provider are unaffected | Implement both. `StubFontMetricsProvider` shows the old approximation — each line's horizontal ink over an `ascent + descent` band, and a `leading` of 0 — so delegate to one only if that is really what the provider means; one with glyph outlines should bound its real ink |
| `LayoutSystem.init` no longer defaults `staffAddresses` and `staffGeometries` to `[]` (`LayoutEngine.stickyHeaderSystem` had been dropping the addresses that way; it now carries the template system's) | Code that constructs a `LayoutSystem` directly, test fixtures mostly | Pass both. `[]` is still accepted, but it means no `StaffAddress → flat-index` map (`flatIndex(for:)` answers `nil`) and every staff five-line. To change a laid-out system, use `addingSpanners(_:)` / `movedBy(dy:)` rather than re-invoking `init` |
| `LayoutDocument.lyricLineY(at:verse:…)`, `lyricEntryOrigin(at:…)` and `textEntryOrigin(kind:at:text:…)` take `placementStyle:`, `elementProperties:` and `textProperties:` without defaults, and the verse-0 `lyricLineY(at:)` overload is gone | Callers that omitted any of the three, or called `lyricLineY(at:)` | Pass the score's `style.textPlacement`, the mark's element properties and its font — for a syllable `LyricInputPlanner.lyric(at:in:)?.elementProperties ?? .default` and `….properties ?? TextProperties()`, for a text annotation `SetElementPlacement.currentProperties(for:in:) ?? .default` and `SetTextFont.current(_:in:) ?? TextProperties()`. The lyric functions still accept `placementStyle: nil`, which keeps the old no-style answer. For verse 0, `lyricLineY(at:verse: 0, placementStyle:elementProperties:textProperties:)` |
| `Instrument.init` no longer takes `drumLineMap:` (the `drumLineMap` property stays, readable and assignable) | Callers that built a drum kit from lines alone | `drumset: GMDrumset.entries` for the GM kit (what `drumLineMap: GMPercussion.drumLineMap` built), or the host's own `[Int: DrumsetEntry]`. For a custom line map, `drumset:` with `GMDrumset.entry(forPitch:line:)` per pitch, or build the instrument and assign `instrument.drumLineMap` — either gives each pitch the GM name, head and voice on the line asked for, as the parameter did |
| `RehearsalMark.FrameKind` (a typealias) is gone | Code that names it | `TextFrameType` — the same type |
| `BravuraFont.familyName` is gone (`BravuraFont.register` stays) | Apple hosts that name it | `SMuFLFamily.bravura` from `SheetMusicLayout` — the same string, `"Bravura"` |
| `LayoutOptionsWire.honorLayoutBreaks` is gone — from the Swift init and from the generated Kotlin `LayoutOptionsWire` — and `breakPolicyRaw = 0` now means `.honor` instead of deferring to it. Its wire tag (3) is reserved, so every other field keeps its tag and a blob that still carries it decodes | Hosts that build a `LayoutOptionsWire`. One that sent `honorLayoutBreaks = 1` (every shipped host) only has to drop the argument. **One that sent `0` and left `breakPolicyRaw` at `0` compiles once the argument is dropped and silently starts honoring breaks** | Drop the argument. To ignore breaks, set `breakPolicyRaw`: `3` ignores line and page breaks (what `honorLayoutBreaks = 0` meant), `2` ignores line breaks only, `1` or `0` honors both |
| Web: `LayoutOptions.honorLayoutBreaks` (`@jiyimeta/sheet-music-web`) is replaced by `breakPolicy?: "honor" \| "ignoreSystemBreaks" \| "ignoreAll"` (default `"honor"`); the raw wasm `LayoutOptions` struct's `honorLayoutBreaks: Bool` is `breakPolicyRaw: Int` with the `LayoutOptionsWire` numbering | Web hosts that pass `honorLayoutBreaks`. TypeScript flags it; plain JavaScript does not, and `honorLayoutBreaks: false` is then ignored — breaks are honored | `breakPolicy: "ignoreAll"` for `honorLayoutBreaks: false`; drop `honorLayoutBreaks: true` |
| Kotlin `SheetMusicJNI.nativeEditingHitTest` (and the Swift `nativeEditingHitTest` behind it) no longer takes `optionsBytes`, which was reserved and ignored | Android callers of `nativeEditingHitTest` | Drop the argument: `nativeEditingHitTest(scoreHandle, xMm, yMm, activeVoice)`. The hit is still re-addressed past the hidden staves the cached layout was computed with |
| The font-metrics install is renamed: wasm / web `installSMuFLMetrics` → `installFontMetrics`, JNI `nativeInstallSMuFLMetrics` → `nativeInstallFontMetrics` (Kotlin `SheetMusicJNI` and the Swift entry point) | Every web and Android host — the install is required before layout | Rename the call. Same payload (`sheet-music.smft` / `FontMetricsBuilder.buildTable`), same `Boolean` result |

## Additions (no action needed)

- `LayoutBridge.computePages(score:pageWidthMM:pageHeightMM:options:)` → `LayoutPages` (pages as commands with each
  system's `SystemSpan`), `LayoutBridge.encodePagesWithSpans(…)`, `DrawRect`.
- `installFontMetricsTable(_:)`: installs `sheet-music.smft` as the layout's font metrics — for hosts without CoreText.
- `SheetMusicRenderWindows.ScoreSurface`: draw-program pages on a composition swap chain or a window (Windows).
- `MasterTuning.effectiveCents(tuning:transposeSemitones:isPercussion:)`.
- `WindowsPlaybackEngine.Event` / `onEvent` (auto-stop at the end, output device lost / recovered) and
  `WindowsPlaybackEngine.Diagnostics` (Windows).

## Fixes (no action needed)

- Android `nativePageBreaks` and the wasm `pageBreaks` resolve the break policy through
  `LayoutOptionsWire.breakPolicy`, as the layout itself does. They read the old boolean, so with
  `breakPolicyRaw = 2` (`.ignoreSystemBreaks`) and the boolean at `0` they reported one page where the draw program
  honored the authored page breaks. The web can now ask for `.ignoreSystemBreaks` at all (`breakPolicy:
  "ignoreSystemBreaks"`).
