# Building the Apple example apps

`Examples/Apple/SheetMusicExample` is an Xcode project (Mac + iOS targets)
that lives outside the SwiftPM package graph. `swift test` and
`Scripts/preflight.sh` never touch it, so it needs its own build record.

## Fresh-worktree setup

The `.xcodeproj` is generated by `xcodegen` from `Examples/Apple/project.yml`
and is gitignored — it does not exist until you generate it, and every fresh
worktree needs to run this step first:

```bash
xcodegen generate --spec Examples/Apple/project.yml --project Examples/Apple
```

`Examples/Apple/SheetMusicExample/Sounds` is also gitignored. It is not
copied into the repo; it is a symlink to the SoundFont set checked out in the
primary checkout, created by:

```bash
Scripts/link-apple-sounds.sh
```

Run this **before** building the Mac target, not only if you intend to play
audio. `project.yml` marks the `Sounds` folder reference `optional: true`,
and that flag is easy to misread as "the build works without it." It does
not: `optional: true` only suppresses `xcodegen`'s generate-time error when
the folder is absent. `xcodebuild`'s `CpResource` step for
`SheetMusicExampleMac` still hard-errors and aborts the build before a single
Swift file compiles:

```
error: The file "Sounds" couldn't be opened because there is no such file.
```

Task 4 of the macOS-foundations plan hit this directly. Treat
`Scripts/link-apple-sounds.sh` as a build prerequisite for
`SheetMusicExampleMac`, not an optional nicety.

The `SheetMusicExample` iOS target excludes `Sounds` from its own sources
(see `project.yml`), so the iOS build does not depend on the symlink.

## Building both targets

```bash
xcodebuild -project Examples/Apple/SheetMusicExample.xcodeproj -scheme SheetMusicExampleMac -destination 'platform=macOS' -skipPackagePluginValidation build
```

```bash
xcodebuild -project Examples/Apple/SheetMusicExample.xcodeproj -scheme SheetMusicExample -destination 'generic/platform=iOS Simulator' -skipPackagePluginValidation build
```
